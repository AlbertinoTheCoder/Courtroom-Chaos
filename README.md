# Courtroom Chaos

Unreal Engine 5.8.3 project with one complete authored case: The Stolen Golden Gavel. Run `LaunchGame.bat` for the standalone Windows game, or open `CourtSimulator.uproject` in Unreal to edit it. Build output is `Builds/Windows/CourtSimulator.exe`.

The case includes consultation, opening statements, three cross-examinations and contradiction resolutions, a closing argument and verdict. Evidence unlocks as deductions reveal new facts. Incorrect presentations reduce credibility; a recess prevents a permanent dead end. Saves are atomic and Continue restores the trial.

Mouse controls the interface. Space advances dialogue, arrows browse testimony, Q presses, E opens the record, H opens the transcript, and Escape goes back or saves to the menu. Tab / Shift-Tab and Enter navigate buttons. Physical exhibits can be dragged or rotated with A/D and zoomed with the wheel. Examine details records a clue in the transcript.

Settings include master/music/effects/voice volume, graphics quality, window mode, text size/speed, instant text, reduced motion and high contrast. The ending shows a performance grade and earned badges.

Six original cartoon characters have 17-bone rigs and 20 authored animation clips each. Desk slams, objections, reactions and the judge's gavel use timed runtime choreography. The case has illustrated documents/photos and 3D mustard/gavel inspection. Six distinct Kokoro voices deliver the case dialogue offline. Speech amplitude drives mouth morphs. Four synchronized procedural music layers build from a courtroom shuffle to percussion and brass as presses, mistakes and objections raise the court temper; dialogue ducks the music.

Editable sources are in `Art/Blender`: `CourtroomFinal.blend`, `CastRigged.blend` and `EvidenceProps.blend`. Runtime case content is the editable Unreal Data Asset `/Game/Cases/DA_GoldenGavel`, generated by `Tools/create_case.py`. The interface uses Unreal Canvas with runtime TrueType glyphs rasterized at the viewport size. Dialogue and contradictions are deterministic and require no external service.

Use `Tools/BuildProject.ps1` to compile, `Tools/BuildArt.ps1` to regenerate art and the Unreal level, and `Tools/PackageGame.ps1` to build the Windows package. Regeneration replaces generated assets, so preserve manual edits first. Scripts use the installed Unreal at `E:/UE_5.8` and Blender at `D:/Blender` and require Python with `requirements.txt` installed.

`Tests/RunTrialTest.ps1` verifies case validation/progression, evidence locks, pressing, incorrect evidence, three deductions, closing/verdict, atomic save/load and corrupt-save recovery, runtime skeletal movement, desk/gavel contact, dialogue coverage, speech pause/resume, mouth morphs and adaptive music. Test saves are separate from player saves. See `Documentation/FinishChecklist.md` for final verification status.

The delivered scope is this single case with procedural cartoon art. Additional cases, recorded voice acting, articulated finger animation and broader hardware testing are future expansion work.

Visual review: launch the editor game or packaged executable with `-CourtVisualTest -RenderOffscreen -ResX=1280 -ResY=720`. This isolated mode renders settings, testimony, record, 3D exhibits, document inspection, transcript, closing, gavel, results, desk slam, credits, case files and the main menu into `Saved/VisualQA`, then exits. It uses test-prefixed saves. Run `Tests/RunTrialTest.ps1 -Packaged` after packaging for the four standalone integration reports; its user data stays under `Saved/PackagedVerification`.

Voice regeneration: `Tools/BuildVoices.ps1` creates an isolated build environment under `Saved/TTS`, downloads the free model once, and bakes dialogue to `Art/Voices`. The game ships the resulting WAV assets and needs no model, Python, account, or internet connection. See `Documentation/AudioCredits.md`.
